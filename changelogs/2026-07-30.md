### 二、🔴 根因一：sitemap 161 条 URL 全部没有 lastmod
配置里 `autoLastmod: false` 且 `transform` 未输出该字段。Google 只用 lastmod 排抓取优先级，`changefreq`/`priority` 明确被忽略 → sitemap 天天被抓（GSC 显示 07-29 20:28 最后一次下载，0 warnings/errors、161 条全提交），但新页/改动页迟迟不被抓取。
修：博客与产品页取数据库真实 `updated_at`（回退 `published_at`）；静态路由（grade-guide、screens/gx|jk 等库里无记录）取该路由源码目录的最后一次 git 提交时间，改页面即自动更新、无需维护日期表。**不用 autoLastmod**——它给所有 URL 盖同一构建时间戳且每次部署都变，Google 会学会不信任。取数失败一律回退「无 lastmod」，不编时间、不阻塞构建。

### 三、🔴 根因二（更严重）：next-sitemap 读不到 env，additionalPaths 长期空转
上一版修完 lastmod 后线上仍是 0 条 → 继续挖：**next-sitemap 是独立进程，不会加载 .env / .env.production**（Next.js 只在 `next build` 自己进程里加载），项目也没装 dotenv → 生成 sitemap 时 `NEXT_PUBLIC_SUPABASE_*` 全是 undefined → `fetchPostSlugs`/`fetchProductSlugs` **一直返回空数组** → `additionalPaths` 长期只贡献 23 条静态路径。
线上那 160 条其实是 next-sitemap 自己扫构建产物得到的，不是数据库清单。直接后果：①未被预渲染的文章（榜单文 id202）根本没进 sitemap ②所有 URL 无 lastmod。
修：配置顶部手工解析 `.env.production`/`.env.local`/`.env`（零新增依赖，已存在的环境变量优先，读不到就跳过）。VPS `.env.production` 已确认含所需两个变量。
