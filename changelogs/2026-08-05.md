## Codex独立Review

Codex以只读模式审查当前未提交diff并独立运行测试，首次结论为 `REQUEST_CHANGES`。

### Codex发现并由Hermes确认的P1问题

1. **Remove只隐藏产品卡，没有清除隐藏category和URL参数。**
   - 产品卡消失后，旧category仍可能进入message和`productInterest`。
   - `pageUrl`仍携带原product/category/productUrl，造成买家以为删除、销售仍收到旧需求的矛盾。

2. **部分真实入口category被映射逻辑静默丢弃。**
   - 现有入口会发送 `iPad Batteries`、`Screen`、`Rear Camera`、`Charging Port` 等值。
   - 删除Products dropdown后，买家没有可见控件补救丢失的category。

Hermes拍板：首次Review不通过，不允许Commit；评分7.5/10，退回一次受限修复。

## Codex受限修复

Codex只修改本次批准的4个文件范围，修复内容：

- 显式`category=`优先使用canonical mapping；没有canonical映射时安全保留清洗后的原category。
- 新增真实入口映射：
  - `iPad Batteries` -> `Batteries`
  - `Screen` -> `LCD/OLED Screens`
  - `Rear Camera` -> `Small Parts`
  - `Charging Port` -> `Small Parts`
- category-only深链也显示可见的`Selected category`摘要，并提供同一个Remove入口。
- `clearDeepLinkSelection()`同时清除：
  - selected product state
  - hidden category state
  - URL中的`product`、`category`、`productUrl`
- URL清理保留其他归因参数及hash，包括UTM、gclid和`#quote-form`。
- Message组装改为确定性的单换行，不再依赖各片段自带前导换行。
- Hermes恢复原有邮件标签和顺序：`Selected product`、`Product source`、`Products`，避免无关兼容性变化。
- Message增加`aria-required`、`aria-invalid`和error association；不增加原生`required`，避免绕过现有自定义错误提示。
- 折叠按钮增加`aria-expanded`、`aria-controls`和稳定panel id。
- 表单契约改为检查精确控件集合和重复控件，不再只是检查“应有/应删除”。
