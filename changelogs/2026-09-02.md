## 18:50 · 修复 P0-2（限流过狠 + UA 误伤）

### 操作类型：修改

### 涉及文件
- `src/middleware.ts`
- `src/app/products/[slug]/page.tsx`

### 变更说明

**1. 真实 IP 取反了（安全）**
nginx 用 `$proxy_add_x_forwarded_for`，展开是「客户端自带值, 真实 IP」——
真实 IP 在**最后**。原代码取 `split(',')[0]`（第一个），等于客户端自己写：
随便加一行 `X-Forwarded-For: 1.2.3.4` 就同时绕过限流和 `BLOCKED_IP_PREFIXES`，
两个月来往黑名单里加的机房段全部形同虚设。新增 `getClientIp()` 取最后一跳。

**2. UA 从「泛化拦截」改成「点名拦截」**
删掉 `/bot/i`、`/crawl/i`、`/spider/i` 三条正则（所有误伤的源头）以及对通用
HTTP 客户端（curl / wget / python-requests / go-http-client / headless 浏览器）
的拦截——真要采集的人改一行 UA 就绕过，这几条实际只挡住了自己的监控与巡检。
- 新增 `BLOCKED_UA_PATTERNS`（25 条）：SEO 数据采集、B2B 名单采集
  （含当天从 nginx 日志抓到的 GlobRadarBot / ApexLeadBot，是当日 403 最大两股）、
  Bytespider / PetalBot、漏洞扫描器
- 白名单补：`applebot`(Siri/Spotlight)、`redditbot`(Reddit 链接预览)、
  `discordbot`、`pinterest`、`telegrambot`、`seznambot`、`googleother`、
  `google-inspectiontool`、`bingpreview`、`adidxbot`、`mastodon`、`bluesky`、
  `embedly` / `iframely` 等
- 其余不认识的 UA：放行但走限流，不再直接 403
- 仍然 403：无 UA / UA 长度 < 10（日志里扫 `/wp-load.php` 那批）、点名黑名单、IP 黑名单

**3. 限流重设**
根因是计数口径：Next.js `<Link>` 默认开预取，一次页面浏览除 HTML 外还带出约
7 个 `?_rsc=` 请求，一页吃 8 次额度 → 60 次只够看 7 个页面。
全站 70 个文件用 next/link，无一处 `prefetch={false}`。
- 预取请求（`next-router-prefetch` / `purpose: prefetch` / 带 `_rsc` 参数）**不计数**
- 页面导航 60 → **240 次/分钟**；`/api/*` 维持 60 次/分钟
- 好爬虫由「完全跳过限流」改为 **600 次/分钟** 兜底
  （原来 skip 等于任何人把 UA 改成 Googlebot 就能无限打）

**4. 429 不再返回纯文本**
HTML 导航返回一个说明页（含 `Retry-After: 60`、`X-Robots-Tag: noindex`
和 WhatsApp 出口 wa.me/85363902425）；RSC / API / 图片等非 HTML 请求保持纯文本。

**5. 前置修复：`/products/[slug]` 的 `revalidate = 0` → `3600`**
这条动态路由排在静态路由之后，所有命中不到的路径都会落到它、各打一次 Supabase。
爬虫扫一批不存在的 URL 就能把库打满，而 08-10 全站 404 的根因正是 Supabase
出站流量爆额度。放宽爬虫闸之前必须先堵上，缓存时长与 `/blog` 系列对齐。
